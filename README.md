### 2026.9.14更新

1. 修复：游玩界面「返回主菜单」不可用，其实是**两个叠加的毛病**
   - 单机模式下按钮被 `visible = false` 藏起来了；
   - `ContentMargin` 是个铺满全屏的容器，而 Godot 里 `Container` 的 `mouse_filter` 默认是 `PASS`，
     它又排在场景树最后（画在最上层），于是把顶栏那条带上的点击**全部吃掉**——
     「返回主菜单」和新增的「聊天」都点不动。已把这些纯排版容器改成 `mouse_filter = IGNORE`。
2. 新增：游玩界面内置聊天（联机对局可互发消息，单机模式只在本机显示）。
   聊天面板**不参与容器排版**，而是按棋盘实际位置摆在棋盘右边的空当里（留 16px 间隙），
   所以开关聊天时**棋盘纹丝不动**，面板也绝不会压住棋盘。
3. 新增：主菜单「棋子指南」——回合流程 + 五种棋子的文字说明（走子、攻击、结算、要点）。
4. 新增：**游玩界面长按棋子弹指南卡片**——按住约 0.4 秒，棋盘左侧空白区弹出该棋子的说明，松手消失。
   卡片矩形 = 左侧空白区、上下铺满整屏（所以「返回主菜单」按钮挪到了右上角）。
   卡片宽度只取决于棋盘位置（不再受聊天面板影响）；放不下时会自动缩小字号，
   再放不下就只保留完整条目并指向「棋子指南」，不会出现半句话。
5. 文案唯一来源：`scripts/piece_guide.gd`（`PieceGuide`）。指南页面与长按卡片都读它，
   测试会检查每种棋子都有说明，并核对指南里写的兵力与真实初始布局一致。
6. 新增：`tests\` 测试套件（服务端协议 / 游玩界面 / 主菜单与指南 / 联机端到端）
   一键运行：`powershell -ExecutionPolicy Bypass -File .\tests\run-tests.ps1`
7. 新增：`deploy\build-release.ps1` 一键导出发布版（自动刷新全局类名缓存、
   检查有没有意外产生独立 `.pck`、校验导出是否真的产出了新文件）。
   服务端启动横幅新增「协议：…」一行 —— **升级后看这行有没有 `chat` 就知道云端换没换成新版**。
8. 新增：**「棋子指南」里插入会动的演示图**（第一批只做了弓）。这不是预渲染的 GIF/视频，
   而是**每一帧都实时问 `rules.gd` 算出来的**：弹道来自 `Rules.attack_targets`、
   击杀来自 `Rules.resolve_kills`。所以改了棋规，演示会跟着变，
   不可能出现「文字说打得到、画面上却打不到」。
   - 演算层 `scripts/demos/guide_demos.gd`（`GuideDemos`）：把一段声明式剧本跑成帧列表，
     里面**没有任何棋规判断**，全是转手问 `Rules`。
   - 绘制层 `scripts/guide_demo.gd`（`GuideDemo`）：`_draw()` 画棋盘、棋子、弹道与阵亡残影，
     自动循环播放；滚出可视区就停，只有真的在播时才请求重绘。
   - **每个回合的时长由剧本声明**：`phases[].duration` 说这个回合演多久，回合内部各帧
     再按权重（列表里的第二个数字，1.5 = 一拍、1.0 = 半拍）摊分。
     所以「某个回合多了两帧就变得特别长」不会悄悄发生；弓的三个回合都是 2.0 秒。
   - **棋盘逐帧动态缩放**：画布按整段演示的最大范围定死（不逐帧变，否则卡片里的文字
     会跟着抖），棋盘在画布内部按当前这一帧的范围缩放，切换时做 0.28 秒的过渡。
     弓这一段是 `4×4`（开局）→ `2×2`（打掉两个绿步，画布收回活着的棋子身上）→ `2×3`（走子后）。
     范围由 `GuideDemos.frame_bounds()` 逐帧算，只算「活着的棋子 + 弹道两端 + 高亮」——
     不算法可走格小点（弓一格能走八格，算上它范围立刻铺满棋盘），也不算正在阵亡的棋子
     （那正是「棋盘该收回来了」的信号）。缩放节奏与「过渡是不是真的在动」都有测试盯着。
   - **棋盘不画外框**：一圈边线跟着缩放反而显眼，棋子与格线已经足够表达棋盘。
   - 剧本与文案同住在 `scripts/piece_guide.gd`（唯一数据源），每种棋子一个 `demos` 字段；
     没写演示的棋子返回空数组，页面照常显示纯文字。
   - 新增测试 `tests/test_guide_demos.gd`：拿真实的 `Rules` 逐帧核对演示里的每一条弹道、
     每一次击杀、以及开局局面里每枚棋子的阵营——改棋规却忘了改演示就会红；
     同时守住逐帧范围与缩放节奏。
     它跑在 `tests\run-tests.ps1` 的第 1.5 步（headless，不弹窗）。

> 本次迁移步骤见 `neo-two-kings\docs\server-deployment.md` 第 0.5 节（速查）与第 8 节（更新服务端）。

> ⚠ **联机聊天需要服务端一起更新**（协议新增了 `chat` 消息）。
> 客户端不更新服务端也能正常对局，只是聊天会被锁掉并提示需要更新服务端。
> 详见 `neo-two-kings\docs\server-deployment.md` 第 8.1、9、10 节。

> ⚠ 界面测试那一步**会短暂弹出游戏窗口**：headless 模式下引擎不派发模拟鼠标事件，
> 而「按钮有没有被上层控件挡住」只有真实命中测试才测得出来（这个 bug 第一版测试就是漏在这）。
