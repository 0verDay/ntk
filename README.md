## neo-two-kings

开发版本

### 2026.9.15更新

1. 新增：**五枚棋子全部配上实时演算教程**（王 / 弓 / 骑×2 / 盾 / 步），框架与绘制都是同一套：
   `GuideDemos` 出帧 → `GuideDemo` 画，每一步都拿真实的 `rules.gd` 现算，改棋规演示会跟着变。

   | 棋子 | 段数 | 流程 | 棋盘 |
   |---|---|---|---|
   | 王 | 1（3 段） | 王区高亮 → 向右下走一格直接吃子 → 拉远看「王区之外一步都去不了」 | 7×7（示意） |
   | 弓 | 1（3 段） | 摆位 → 向右下走一格 → 双盾当炮架，**横**一条、**斜**一条同时双杀 | 6×6 |
   | 骑 A | 1（3 段） | 摆位 → **两段箭头画出连跳轨迹** (4,2)→(2,0)→(0,2) → 落在 (0,2) | 7×7 |
   | 骑 B | 1（3 段） | 摆位 → 骑**向左走一格**贴上去 → 借敌人身后的自己人**夹击**击杀 | 7×7 |
   | 盾 | 1（2 段） | 敌步朝下打我的盾、盾身后紧挨着自己的步 → **抵抗**成功；把那枚撤走 → 同一发当场打死盾 | 7×7 |
   | 步 | 1（3 段） | 摆位 → 上方的步向下走一格 → 靠**队列厚度**（1:0）吃掉敌人 | 7×7 |

   - 骑 A 与骑 B 是**一对**：A 只讲走位（连跳后落在敌人旁边却**打不动**，因为敌人身后空了），
     B 才讲击杀（同样的敌人，身后有自己人，一夹就死）。这样「跳得到 ≠ 打得到」一眼看清。
   - 盾那段的关键是「身后」要**沿着攻击方向**算：敌人从上往下打，(2,4) 才算盾的身后。
     另外，敌步之所以「本来打得动」，是因为它自己身后连着两枚绿步（队列 2:0）——
     抵抗是在这一击**已经成立**之后把它作废的，这才是盾的价值所在。

2. 演示框架的几处扩展（都为了上面这些教程，且不改变原有几段的语义）：
   - **跳跃步骤** `["hop", w, {from, to, path?}]`：骑的连跳。每一段都必须「越过相邻的一子、落到它正后方」，
     逐段画箭头（(4,2)→(2,0)→(0,2) 这种折线用 `path` 写明中间落点，轨迹一眼看得出）。
   - **撤走步骤** `["remove", w, {cells}]`：把棋子从局面上拿掉。盾的第二段靠它——
     撤掉盾身后的自己人，同一发攻击就从「被抵抗」变成「打中」，这是**局面**变了，不是显示层能糊弄的。
   - **结算方按棋子自己的阵营**：`["shots", …]` 不再写死红方，而是取「站在 `at` 上那枚棋子」的阵营——
     所以**敌方也能开火**，盾的「被抵抗」才有得演。
   - 另有 `zones`（王的王区高亮）、`pieces` / `cleared`（只改某一帧的显示）、
     `board_pieces`（**修正阵营**的示意图写法 `[兵字, 阵营]`）几个键，供「棋盘拉远 / 示意图」这类帧使用。
   - 棋盘边长改成由剧本的 `size` 声明，`state_of` 与 `build` 共用同一个数——它同时决定双方半场，
     猜错就会出现「画面上是敌人、规则里却是自己人」（这个坑我踩了不止一次）。

3. 修复：**游玩界面「长按棋子弹指南卡片」不可靠**——按住 0.4 秒有时不弹，偶尔干脆永远不弹。
   - 根因：长按计时原来是**逐帧累加 `_process(delta)`**。引擎在窗口失焦/被遮挡时会压缩
     每帧的 delta（实测一拍仍然只给 ~0.017 秒，而 `SceneTreeTimer` 用的是真实时间），
     于是「累加出来的时间」远慢于玩家手上真实按住的时间——按满 0.4 秒，账上可能才过了 0.2 秒。
   - 现在改成**按墙上时钟**算（`Time.get_ticks_msec()` 记按下时刻，见 `Board._press_held_seconds`），
     并让 `_process` 与 `_input` 一起对表（引擎跳帧时，下一个输入事件也能把它补上）。
   - 这个 bug 之前一直被测试放过：测试在 `create_timer(long_press_duration + 0.15)` 之后才断言，
     而**多出来的 0.15 秒正好够旧代码把账凑到 0.4**；一旦机器卡一下，差额就补不回来，
     表现为随机失败（实测 5 次里 1 次、6 次里 4 次）。修复后连跑 8 次全绿。

> 带 `schematic` 的演示（王、骑 A、骑 B、盾）里，有几枚棋子的阵营是**指定**的：
> 真实半场由反对角线切分，而这几张紧凑的教具摆位会把敌人放进红方地界——真实棋规下摆不出来。
> 这些段落只在**摆位/阵营**上让步（`board_pieces` 的 `[兵字, 阵营]` 写法），
> 能不能吃、能不能打、谁被抵抗，仍然全部由 `Rules` 现算（画面与规则用同一份结果）；
> 演示测试会跳过这几段的「棋子都在自己半场」一项，其余断言照常。骑 A 还声明了 `no_kill`（它只演示走位）。
>
> 全套测试：协议 31 项 / 指南演示 188 项 / 界面 59 项 / 主菜单与指南 19 项 / 联机 11 项，全部通过。

### 2026.9.14更新

1. 修复：游玩界面「返回主菜单」不可用，其实是**两个叠加的毛病**
   - 单机模式下按钮被 `visible = false` 藏起来了；
   - `ContentMargin` 是个铺满全屏的容器，而 Godot 里 `Container` 的 `mouse_filter` 默认是 `PASS`，
     它又排在场景树最后（画在最上层），于是把顶栏那条带上的点击**全部吃掉**——
     「返回主菜单」和新增的「聊天」都点不动。已把这些纯排版容器改成 `mouse_filter = IGNORE`。
2. 新增：游玩界面内置聊天（联机对局可互发消息，单机模式只在本机显示）。
   聊天面板**不参与容器排版**，而是按棋盘实际位置摆在棋盘右边的空当里（留 16px 间隙），
   所以开关聊天时**棋盘纹丝不动**，面板也绝不会压住棋盘。
3. 新增：主菜单「棋子指南」——回合流程 + 五种棋子的文字说明（走子、攻击、结算、要点）。
4. 新增：**游玩界面长按棋子弹指南卡片**——按住约 0.4 秒，棋盘左侧空白区弹出该棋子的说明，松手消失。
   卡片矩形 = 左侧空白区、上下铺满整屏（所以「返回主菜单」按钮挪到了右上角）。
   卡片宽度只取决于棋盘位置（不再受聊天面板影响）；放不下时会自动缩小字号，
   再放不下就只保留完整条目并指向「棋子指南」，不会出现半句话。
5. 文案唯一来源：`scripts/piece_guide.gd`（`PieceGuide`）。指南页面与长按卡片都读它，
   测试会检查每种棋子都有说明，并核对指南里写的兵力与真实初始布局一致。
6. 新增：`tests\` 测试套件（服务端协议 / 游玩界面 / 主菜单与指南 / 联机端到端）
   一键运行：`powershell -ExecutionPolicy Bypass -File .\tests\run-tests.ps1`
7. 新增：`deploy\build-release.ps1` 一键导出发布版（自动刷新全局类名缓存、
   检查有没有意外产生独立 `.pck`、校验导出是否真的产出了新文件）。
   服务端启动横幅新增「协议：…」一行 —— **升级后看这行有没有 `chat` 就知道云端换没换成新版**。
8. 新增：**「棋子指南」里插入会动的演示图**（第一批只做了弓）。这不是预渲染的 GIF/视频，
   而是**每一帧都实时问 `rules.gd` 算出来的**：弹道来自 `Rules.attack_targets`、
   击杀来自 `Rules.resolve_kills`。所以改了棋规，演示会跟着变，
   不可能出现「文字说打得到、画面上却打不到」。
   - 演算层 `scripts/demos/guide_demos.gd`（`GuideDemos`）：把一段声明式剧本跑成帧列表，
     里面**没有任何棋规判断**，全是转手问 `Rules`。
   - 绘制层 `scripts/guide_demo.gd`（`GuideDemo`）：`_draw()` 画棋盘、棋子、弹道与阵亡残影，
     自动循环播放；滚出可视区就停，只有真的在播时才请求重绘。
   - **每个回合的时长由剧本声明**：`phases[].duration` 说这个回合演多久，回合内部各帧
     再按权重（列表里的第二个数字，1.5 = 一拍、1.0 = 半拍）摊分。
     所以「某个回合多了两帧就变得特别长」不会悄悄发生；弓的三个回合都是 2.0 秒。
   - **棋盘逐帧动态缩放**：画布按整段演示的最大范围定死（不逐帧变，否则卡片里的文字
     会跟着抖），棋盘在画布内部按当前这一帧的范围缩放，切换时做 0.28 秒的过渡。
     弓这一段是 `4×4`（开局）→ `2×2`（打掉两个绿步，画布收回活着的棋子身上）→ `2×3`（走子后）。
     范围由 `GuideDemos.frame_bounds()` 逐帧算，只算「活着的棋子 + 弹道两端 + 高亮」——
     不算法可走格小点（弓一格能走八格，算上它范围立刻铺满棋盘），也不算正在阵亡的棋子
     （那正是「棋盘该收回来了」的信号）。缩放节奏与「过渡是不是真的在动」都有测试盯着。
   - **棋盘不画外框**：一圈边线跟着缩放反而显眼，棋子与格线已经足够表达棋盘。
   - 剧本与文案同住在 `scripts/piece_guide.gd`（唯一数据源），每种棋子一个 `demos` 字段；
     没写演示的棋子返回空数组，页面照常显示纯文字。
   - 新增测试 `tests/test_guide_demos.gd`：拿真实的 `Rules` 逐帧核对演示里的每一条弹道、
     每一次击杀、以及开局局面里每枚棋子的阵营——改棋规却忘了改演示就会红；
     同时守住逐帧范围与缩放节奏。
     它跑在 `tests\run-tests.ps1` 的第 1.5 步（headless，不弹窗）。
