### 新增：指南关键帧的可视化编辑器

改演示不用再写代码了：

```bash
python tools/editor/editor.py      # 只用到标准库 tkinter，不用起服务也不用浏览器
```

界面四块：左边是**回合 / 关键帧**的树，中间是**棋盘**（选工具后在格子上点就能摆子/擦除/
设起点终点/设结算格/加高亮/设撤走），右边是**属性**（文字、时长、权重、坐标），底下是状态栏
（实时校验）。`Ctrl+S` 保存 → 写回 `tools/demos/*.py` 并刷新 `data/guide_demos.json` → 回游戏里看。

1. **只重写「剧本区」**：每个模块里 `# --- 剧本区开始 ---` 到 `# --- 剧本区结束 ---` 之间是数据，
   编辑器整段重写；**文件开头的说明文档与 import 原样保留**（那些「为什么这么摆位」的话不会丢）。
   import 行会按需要补齐（只加不减），免得新加一种关键帧就 `NameError`。
2. **保存是安全的**：先把生成的源码 `compile()` 一遍，再原子写入（写临时文件再替换）；
   校验不过（比如某一帧没写文字）会直接拒绝保存。`Ctrl+Z` 撤销、`Ctrl+R` 重新载入。
3. **编辑器不做棋规判断**：棋盘上不画弹道、不画阵亡——那是游戏里 `rules.gd` 现算的。
   走过一次结算之后被打死的棋子仍然画在棋盘上，状态栏会提醒你；棋子颜色按半场推算
   （左下角有小点的表示阵营是写死的），唯一真值仍是 `rules.gd`。
4. 新增 `tools/editor/selftest.py`（46 项，不写磁盘）：守「编辑器不会把剧本改坏」——
   磁盘上的模块必须已经是规范形式（所以「打开就保存」不产生无谓改动）、渲染 → 再载入的数据
   必须一字不差、渲染必须幂等、走剧本的记账要和游戏端一致。`run-tests.ps1` 第 0 步会顺带跑它。
5. 为了让编辑器能往返，六个模块统一成「说明 + 纯数据剧本区」的形式：`king.py` 里那个
   `_king_board()` 辅助函数展开成了字面量（数据一字未变，导出出的 JSON 与迁移前逐字节相同）。

> 编辑器第一版实测踩到的坑，记在这儿免得再犯：把九个工具按钮排成一行，按钮的「请求宽度」
> 加起来会把窗口撑到屏幕外面，右栏（属性）整块被挤出去；用 `ttk.Panedwindow` 分栏时，
> 窗口首次映射/缩放会让分栏位置跳一下，同样能把右栏挤没。现在三栏是 grid 定宽列，
> 工具条竖排、三个控件格子写死尺寸并关掉 `propagate`。

### 指南演示改成「纯动画」+ 编辑器只剩三个工具

按需求给指南演示做了一次**减法**：

1. **游戏不再拿 rules.gd 演算关键帧**，只按顺序把帧画出来。每一帧就是一张画：
   画哪几枚棋子、画哪几条箭头、高亮哪些格子、下面写哪句话、停多久。
   数据结构塌成两层：`Demo(caption, size, frames=[Frame(...)])`——原来的「回合 + 权重 +
   走子/连跳/撤走/结算」整套演算层删掉了（`guide_demos.gd` 从 1015 行降到约 330 行；
   `guide_demo.gd` 去掉残影、可走格小点、结算发光）。
2. **编辑器只剩三个工具**：`摆子`（左键放、右键擦）、`箭头`（点起点再点终点；右键取消或删）、
   `高亮`（左键切换）。阵营是选出来的（`red("王")` / `green("步")`），不再按半场推；
   一帧一帧都是**全量**棋子——想演「谁没了」就在下一帧里别写它。
   `Frame.hold` 就是「这一帧停多久」，不再有「回合时长 + 权重摊分」。
3. **内容照迁移**：先把现在这 6 段按棋规算出来的帧原样导出，再烤成新的帧数据，
   逐帧比对确认**棋子、箭头、高亮、文字、停留时间一字不差**（连缩放节奏都还是
   5×4 → 5×4 → 4×3 → 2×2）。改的是**机制**，玩家看到的东西没变。
4. 测试跟着换：`test_guide_demos.gd` 从「拿真 Rules 对账」（221 项，含大量棋规断言）改成
   「帧数据本身对不对、画不画得出来」（91 项：文字 / hold / 越界 / 重复帧 / 画布 / 缩放 / 播放）；
   编辑器自检 49 项照旧（渲染往返不丢信息、每个编辑操作、重新载入真的读盘）。

> ⚠ **主动放弃的保护**：以前「改棋规，演示会跟着变」，也不可能出现「文字说打得到、画面上却打不到」；
> 现在画面完全由你摆的样子决定。改棋规之后请自己回来核对这几段演示——测试不再替你看了。

> 迁移时顺手抓到并修掉一个问题：**上一版编辑器把 `shield.py` 改坏了**——它的「类型」下拉框
> 在一次调试运行里发过假事件（经典 Tkinter 坑：`StringVar` 没留引用被 GC，控件就自己发
> `<<ComboboxSelected>>`），把盾的「结算」帧重建成了 `expect(...)`，还往棋盘上多塞了 3 枚棋子。
> 旧测试看不见（示意图段落的「确实打死了棋子」检查本来就短路）。现在编辑器的**类型下拉框整个没有了**
> （只剩三个工具），Tk 变量也统一留引用；`schematic` / `board_pieces` 这些概念随之下线。

### 指南演示改成「Python 工具 → JSON」

> （已被上面那一版取代：现在不再有 `phases` / `steps`，也不再拿棋规演算；下面这段保留作记录。）

改指南里那些会动的演示，现在不用再碰 GDScript 了。作者只在 `tools/demos/*.py` 里写
**棋子、关键帧、文字**这三样，打谁/谁死/能不能走一律由游戏现算：

```
tools/demos/*.py                        你写剧本的地方
    ↓  python tools/export_guide_demos.py
neo-two-kings/data/guide_demos.json     游戏读它（别手改）
    ↓  GuideDemos.load_scripts() → GuideDemos.build()
帧列表（局面 / 弹道 / 阵亡 / 高亮 / 文字）→ GuideDemo 画出来
```

1. 新增仓库根的 `tools/`（只用标准库，不需要 pip 装东西）：`guide_demo_kit.py`
   （作者 API + 校验 + 序列化）、`demos/{king,archer,knight,shield,pawn}.py`（五个兵种的剧本，
   骑有两段）、`export_guide_demos.py`（命令行：校验 → 写出 JSON）。
   用法与字段速查见 `tools/README.md`。
2. 现有 6 段演示**全部迁移**到 Python，`piece_guide.gd` 里只剩文字（说明/打法），
   不再有手写剧本——JSON 成了演示的唯一数据源，游戏端只读它。
3. 导出前会逐段校验：棋子字、坐标是否在盘内、每回合 `duration > 0`、
   **每个关键帧都必须写一句文字**、字段名拼写、回合名不重复……任何一条不过就一行都不写。
   棋规层面的合法性**不**在 Python 里判（那会多出第二份棋规），仍由 `rules.gd` 现算：
   剧本写错了会在日志里打 ERROR，并由 `test_guide_demos.gd` 变红。
4. `run-tests.ps1` 新增第 0 步：用 `--check` 对比剧本与 JSON，防止「改了 Python 忘了导出」
   （没装 python 时自动跳过，只提醒不判红）。指南演示测试也从 188 项涨到 **221 项**。
5. 导出配置补了 `include_filter="data/*.json"`：`.json` 在 Godot 里**不是**资源，
   不加这一条，导出的客户端里会没有那份 JSON（指南就只剩文字）。已用一次真实导出验证过。

顺手修掉三个之前查出来的毛病（都补了防回归断言）：

- **`expect`/`zone` 帧的文案全丢**：`_frame()` 把 `text`/`moves_text` 写死成空串，
  只有走子/结算那几条路径回头手动抄了一遍，于是「摆位」和讲结论的那几帧棋盘下方一片空白
  （王与骑 A 各有一半以上时间没有解说）。现在 `_frame()` 默认从 step 抄。
- **骑 A（连跳）的阵营与文案相反**：7×7 上 `(4,2)` 按半场算属**绿**方、`(1,1)` 属**红**方，
  画面上其实是「绿骑 + 两枚红步」，而文案写的是「红骑 + 绿敌」——第三段的结论
  （打不动是因为敌人背后空了）也就不成立（真实原因是那枚棋子其实是自己人）。
  现在用 `board_pieces` 显式写明阵营，并加了「示意图的敌我与文案一致」用例。
- **盾那段吐了两帧一模一样的**：空放时先补一帧说明、又无条件补一帧弹道帧，
  同一句话停 1.88 秒，而这一段真正的铺垫只有 0.625 秒。现在两者二选一。

> 还没动的两处（记在这里免得忘）：绘制层的**残影**取的是「整段演示会死的那些格子」，
> 于是被淡出的是**还没死**的棋子（盾那段连盾自己都全程半透明），真正阵亡时反而直接消失；
> 另外 `hop` 箭头在绘制层没有 `kind` 分支，连跳轨迹和攻击弹道是同一个红色，
> 注释里承诺的「跳板」`crossed` 也一直没实现。

### 2026.9.15更新

1. 新增：**五枚棋子全部配上实时演算教程**（王 / 弓 / 骑×2 / 盾 / 步），框架与绘制都是同一套：
   `GuideDemos` 出帧 → `GuideDemo` 画，每一步都拿真实的 `rules.gd` 现算，改棋规演示会跟着变。

   | 棋子 | 段数 | 流程 | 棋盘 |
   |---|---|---|---|
   | 王 | 1（3 段） | 王区高亮 → 向右下走一格直接吃子 → 拉远看「王区之外一步都去不了」 | 7×7（示意） |
   | 弓 | 1（3 段） | 摆位 → 向右下走一格 → 双盾当炮架，**横**一条、**斜**一条同时双杀 | 6×6 |
   | 骑 A | 1（3 段） | 摆位 → **两段箭头画出连跳轨迹** (4,2)→(2,0)→(0,2) → 落在 (0,2) | 7×7 |
   | 骑 B | 1（3 段） | 摆位 → 骑**向左走一格**贴上去 → 借敌人身后的自己人**夹击**击杀 | 7×7 |
   | 盾 | 1（2 段） | 敌步朝下打我的盾、盾身后紧挨着自己的步 → **抵抗**成功；把那枚撤走 → 同一发当场打死盾 | 7×7 |
   | 步 | 1（3 段） | 摆位 → 上方的步向下走一格 → 靠**队列厚度**（1:0）吃掉敌人 | 7×7 |

   - 骑 A 与骑 B 是**一对**：A 只讲走位（连跳后落在敌人旁边却**打不动**，因为敌人身后空了），
     B 才讲击杀（同样的敌人，身后有自己人，一夹就死）。这样「跳得到 ≠ 打得到」一眼看清。
   - 盾那段的关键是「身后」要**沿着攻击方向**算：敌人从上往下打，(2,4) 才算盾的身后。
     另外，敌步之所以「本来打得动」，是因为它自己身后连着两枚绿步（队列 2:0）——
     抵抗是在这一击**已经成立**之后把它作废的，这才是盾的价值所在。

2. 演示框架的几处扩展（都为了上面这些教程，且不改变原有几段的语义）：
   - **跳跃步骤** `["hop", w, {from, to, path?}]`：骑的连跳。每一段都必须「越过相邻的一子、落到它正后方」，
     逐段画箭头（(4,2)→(2,0)→(0,2) 这种折线用 `path` 写明中间落点，轨迹一眼看得出）。
   - **撤走步骤** `["remove", w, {cells}]`：把棋子从局面上拿掉。盾的第二段靠它——
     撤掉盾身后的自己人，同一发攻击就从「被抵抗」变成「打中」，这是**局面**变了，不是显示层能糊弄的。
   - **结算方按棋子自己的阵营**：`["shots", …]` 不再写死红方，而是取「站在 `at` 上那枚棋子」的阵营——
     所以**敌方也能开火**，盾的「被抵抗」才有得演。
   - 另有 `zones`（王的王区高亮）、`pieces` / `cleared`（只改某一帧的显示）、
     `board_pieces`（**修正阵营**的示意图写法 `[兵字, 阵营]`）几个键，供「棋盘拉远 / 示意图」这类帧使用。
   - 棋盘边长改成由剧本的 `size` 声明，`state_of` 与 `build` 共用同一个数——它同时决定双方半场，
     猜错就会出现「画面上是敌人、规则里却是自己人」（这个坑我踩了不止一次）。

3. 修复：**游玩界面「长按棋子弹指南卡片」不可靠**——按住 0.4 秒有时不弹，偶尔干脆永远不弹。
   - 根因：长按计时原来是**逐帧累加 `_process(delta)`**。引擎在窗口失焦/被遮挡时会压缩
     每帧的 delta（实测一拍仍然只给 ~0.017 秒，而 `SceneTreeTimer` 用的是真实时间），
     于是「累加出来的时间」远慢于玩家手上真实按住的时间——按满 0.4 秒，账上可能才过了 0.2 秒。
   - 现在改成**按墙上时钟**算（`Time.get_ticks_msec()` 记按下时刻，见 `Board._press_held_seconds`），
     并让 `_process` 与 `_input` 一起对表（引擎跳帧时，下一个输入事件也能把它补上）。
   - 这个 bug 之前一直被测试放过：测试在 `create_timer(long_press_duration + 0.15)` 之后才断言，
     而**多出来的 0.15 秒正好够旧代码把账凑到 0.4**；一旦机器卡一下，差额就补不回来，
     表现为随机失败（实测 5 次里 1 次、6 次里 4 次）。修复后连跑 8 次全绿。

> 带 `schematic` 的演示（王、骑 A、骑 B、盾）里，有几枚棋子的阵营是**指定**的：
> 真实半场由反对角线切分，而这几张紧凑的教具摆位会把敌人放进红方地界——真实棋规下摆不出来。
> 这些段落只在**摆位/阵营**上让步（`board_pieces` 的 `[兵字, 阵营]` 写法），
> 能不能吃、能不能打、谁被抵抗，仍然全部由 `Rules` 现算（画面与规则用同一份结果）；
> 演示测试会跳过这几段的「棋子都在自己半场」一项，其余断言照常。骑 A 还声明了 `no_kill`（它只演示走位）。
>

### 2026.9.14更新

     所以「某个回合多了两帧就变得特别长」不会悄悄发生；弓的三个回合都是 2.0 秒。
   - **棋盘逐帧动态缩放**：画布按整段演示的最大范围定死（不逐帧变，否则卡片里的文字
     会跟着抖），棋盘在画布内部按当前这一帧的范围缩放，切换时做 0.28 秒的过渡。
     弓这一段是 `4×4`（开局）→ `2×2`（打掉两个绿步，画布收回活着的棋子身上）→ `2×3`（走子后）。
     范围由 `GuideDemos.frame_bounds()` 逐帧算，只算「活着的棋子 + 弹道两端 + 高亮」——
